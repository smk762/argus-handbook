# GPU host

## Minimal setup

1. Install the NVIDIA driver. Curator's GPU image ships CUDA 13 wheels, so the
   driver must support CUDA 13. `nvidia-smi` shows the highest CUDA version the
   driver supports.
2. Install Docker Engine and the NVIDIA Container Toolkit, then check that a
   container can see the GPU:

   ```bash
   docker run --rm --gpus all ubuntu nvidia-smi
   ```

3. In Studio, layer the GPU override on top of the stack:

   ```bash
   docker compose -f compose.yaml -f compose.gpu.yaml --profile full up
   ```

### Sharing one GPU

Lens, curator and Ollama can all load models onto the same card. With
`ARGUS_GPU_COORDINATOR=lease` (set by `compose.gpu.yaml`), cortex's
`argus_cortex.gpu` makes them take turns through a lock file. **Every
container must mount the same lock directory** (`ARGUS_GPU_LOCK_DIR`, mounted
at `/run/argus-gpu`), or each one gets its own lock and they no longer wait for
each other. Lens unloads idle models after `ARGUS_MODEL_IDLE_SECONDS` (300 by
default) to give VRAM back.

argus-puppet's GPU image takes the same lease (kind `pose`) for its own work,
and its CPU image takes none. A service that holds a lease on the card while it
waits for puppet's answer can starve puppet's lease; run puppet on the CPU, or
on another card, to avoid it (see [Body pose](/setup/body-pose#the-limits)).

ComfyUI usually runs outside the stack on the same host, and the stack reaches it at
`http://host.docker.internal:8188`. It doesn't take part in the lease, so a big
render can still collide with a caption run.

Immich's machine-learning server is in the same position when it runs on this
host (see [Remote machine learning on the GPU host](/setup/services/immich#remote-machine-learning-on-the-gpu-host)).
It doesn't take part in the lease either. It gives VRAM back only through its
own idle unload (`MACHINE_LEARNING_MODEL_TTL`). [argus-iris](https://github.com/smk762/argus-iris)
(0.2.1 and later) can name it and, if you opt in, stop it when a lease needs the
room. While it's stopped, Immich falls back to the next URL in its list, so set
one up first.

1. Add `immich_machine_learning` to `IRIS_AGENT_CONTAINERS` on this host's iris
   agent. The broker can't start or stop any container that isn't listed there.
2. Add it under `services:` in the broker config (`IRIS_CONFIG`). Leave out
   `evict_by` to have iris report its VRAM and never stop it:

   ```yaml
   - id: immich-ml
     node: gpu-host             # this host's node id in the same file
     adapter: external
     base_url: "http://gpu-host:3003"
     health_path: /ping
     container: immich_machine_learning
     evict_by: stop
   ```

3. Add it under `residents:` in the policy file (`IRIS_POLICY`):

   ```yaml
   - match: { resident: "gpu-host/immich-ml" }
     enforce: false
   ```

   With `enforce: false` the dashboard shows that iris would stop it for a lease
   and does nothing. Set it to `true` once **Stop** and starting it again have both
   worked by hand. Iris can't see Immich's work in flight, so it goes by how long
   the container has been idle. It starts a container it stopped for a lease again
   once no lease is active on the host.

How it was built: [smk762/argus-iris#29](https://github.com/smk762/argus-iris/issues/29).
